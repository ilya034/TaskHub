
## Задание: Task API - CRUD задач

Необходимо реализовать `TasksController` по аналогии с `UsersController`: обычный CRUD для задач. Каждая задача должна быть **привязана к пользователю**, который её создал.

### Требования к реализации

#### 1) Контроллер `TasksController`

Сделайте контроллер по стилю как `UsersController` (тот же подход к ответам и проверкам).

Нужны методы:

1. **Создать задачу**
	- `POST /tasks`
	- принимает тело `CreateTaskRequest`
	- возвращает созданную задачу (`TaskResponse`) и `201` Created

2. **Получить все задачи**
    - `GET /tasks`
	- возвращает список `TaskResponse`

3. **Получить задачу по id**
	- `GET /tasks/{id:guid}`
	- возвращает `TaskResponse` или `404` NotFound

4. **Изменить название задачи**
	- `PUT /tasks/{id:guid}/title`
	- принимает `SetTaskTitleRequest`
	- возвращает `204` NoContent

5. **Удалить задачу по id**
	- `DELETE /tasks/{id:guid}`
	- возвращает `204` NoContent или `404` NotFound

6. **Удалить все задачи**
	- `DELETE /tasks`
	- возвращает `204` NoContent
#### 2) Модель задачи и привязка к пользователю

Создайте модель задачи отдельно от `UserModel` (его не трогать).
Минимально в задаче должно быть:
- `Id : Guid`
- `Title : string?`
- `CreatedByUserId : Guid` — кто создал задачу
- `CreatedUtc : DateTimeOffset`
#### 3) Хранение в базе данных

Нужно, чтобы задачи реально сохранялись в БД.

Сделайте:

- сущность для EF Core (например, `TaskEntity`)
- контекст `TaskDbContext`
- `DbSet<TaskEntity> Tasks`

Важно: в `TaskDbContext` должна быть настроена **связь один ко многим** между пользователем и задачами:
- задача содержит `CreatedByUserId`
- `CreatedByUserId` — это **внешний ключ** на таблицу пользователей (`users`)
- один пользователь может иметь много задач
#### 4) Репозиторий задач

Сделайте репозиторий по аналогии с тем, как устроено у пользователей.

Интерфейс должен содержать операции:
- создать задачу
- получить все задачи
- получить задачу по id
- обновить название задачи
- удалить по id (с результатом `true/false`)
- удалить все

Реализация репозитория должна работать через EF Core контекст `TaskDbContext`.
#### 5) UseCase слой

Сделайте usecase’ы по аналогии с `CreateUserUseCase` и остальными.

Минимальный набор классов:
- `CreateTaskUseCase`
- `GetTasksUseCase`
- `GetTaskUseCase`
- `SetTaskTitleUseCase`
- `DeleteTaskUseCase`
- `DeleteTasksUseCase`
#### 6) TaskService

Сделайте `ITaskService` и реализацию `TaskService`, как у `UserService`:

- сервис содержит зависимости на usecase’ы
- сервис вызывает `ExecuteAsync(...)` у нужного usecase
#### 7) Регистрация в DI

Нужно зарегистрировать в контейнере:
- `TaskDbContext`
- репозиторий задач 
- все usecase’ы задач
- `ITaskService` / `TaskService`
